## Mach Message Structure Details

A complete Mach message has the following structure:

```
┌─────────────────────────────────────┐
│       Message Header (24 bytes)    │  Offset 0-23
├─────────────────────────────────────┤
│  msg_bits (4) │ msg_size (4)       │  Offset 0-7
│  remote_port (4) │ local_port (4)  │  Offset 8-15
│  voucher_port (4) │ msg_id (4)     │  Offset 16-23
├─────────────────────────────────────┤
│      Descriptor Section (Optional)  │  Offset 24+
├─────────────────────────────────────┤
│  descriptor_count (4)              │  Offset 24-27
│  descriptor_1                      │  Offset 28+
│  descriptor_2                      │
│  ...                               │
├─────────────────────────────────────┤
│           Message Body              │  Offset (24+descriptor_total_size)+
├─────────────────────────────────────┤
│         Trailer (Optional)          │  End of message
└─────────────────────────────────────┘
```

### 1. Message Header (mach_msg_header_t, 24 bytes)
- **msg_bits** (offset 0): When value < 0, indicates OOL message containing descriptor section
- **msg_size** (offset 4): **Note**: This field ostensibly indicates message size, but in actual message validation functions, this field's value may differ from the actual message size. Please prioritize filling this field according to actual constraint conditions in the code
- **remote_port** (offset 8): Target port
- **local_port** (offset 12): Source port
- **voucher_port** (offset 16): Voucher port
- **msg_id** (offset 20): Message ID, identifying specific function

### 2. Descriptor Section (exists only when msg_bits < 0)
- **descriptor_count** (offset 24): Number of descriptors
- **Descriptor sequence**: Starting from offset 28, contains the following three types:

#### OOL Data Descriptor (16 bytes)
```cpp
typedef struct {
    void*     address;      // 8 bytes - Memory address of OOL data
    uint32_t  size;         // 4 bytes - Data size
    uint8_t   deallocate;   // 1 byte - Whether memory needs to be freed (0-1)
    uint8_t   copy;         // 1 byte - Copy method (0-4)
    uint8_t   pad1;         // 1 byte - Padding byte
    uint8_t   type;         // 1 byte - Descriptor type (value = 1)
} mach_msg_ool_descriptor_t;
```

#### Port Descriptor (12 bytes)
```cpp
typedef struct {
    mach_port_t  name;         // 4 bytes - Port name
    uint32_t     pad1;         // 4 bytes - Padding field 1
    uint16_t     pad2;         // 2 bytes - Padding field 2
    uint8_t      disposition;  // 1 byte - Port rights type (16-26)
    uint8_t      type;         // 1 byte - Descriptor type (value = 0)
} mach_msg_port_descriptor_t;
```

#### OOL Port Array Descriptor (20 bytes)
```cpp
typedef struct {
    mach_port_t* address;      // 8 bytes - Address pointing to port array
    uint32_t     count;        // 4 bytes - Number of ports
    uint8_t      deallocate;   // 1 byte - Whether memory needs to be freed (0-1)
    uint8_t      copy;         // 1 byte - Copy method (0-4)
    uint8_t      disposition;  // 1 byte - Port rights type (16-26)
    uint8_t      type;         // 1 byte - Descriptor type (value = 2)
    uint32_t     pad;          // 4 bytes - Padding for alignment
} mach_msg_ool_ports_descriptor_t;
```

### 3. Message Body Section
Message body contains actual parameter data

### 4. Trailer Section (Optional)
Trailer contains additional metadata, such as sender's authentication token

## Constraint Analysis Guidelines

### Descriptor Identification Method
Determine descriptor type based on type field offset position and check value:
- Like `*(unsigned short*)(a1+38) << 16 = 1114112`, where 1114112 = 0x00110000, the two-byte value at offset 38 is 0x0011. Due to little-endian reading, this indicates offset 38 value is 0x11, offset 39 value is 0x00. Based on message header size 24 and port descriptor structure, this descriptor type is port descriptor, disposition value is 0x11, type value is 0x00.
- Similarly, `*(unsigned short*)(a1+38) << 16 = 1179648`, 1179648 = 0x00120000, indicates offset 38 value is 0x12, offset 39 value is 0x00, this descriptor type is port descriptor, disposition value is 0x12, type value is 0x00.
- Similarly, `*(unsigned char*)(a1+39) << 24 = 0x1000000`, since left-shifted by 24 bits, this checks one byte at offset 39, indicating offset 39 value is 0x01, this descriptor type is OOL data descriptor, type value is 0x01.

### Message Body Offset Calculation
For OOL messages, message body start offset = 24 + 4 + (total descriptor size)
Example: If there are 2 port descriptors, message body offset = 24 + 4 + (2 × 12) = 52
